# Verification — 2026-10-25

## Current build

- **v0.4.0 has native Windows Setup, pacman and Debian/Ubuntu packages.** Python 3.14.9 and Qt/PySide 6.12.0 are bundled. The updated Linux OCR helper is static musl; the Windows x64 helper uses official Rust 1.98.1 and llvm-mingw 20261020. End users do not need Python or Rust installed.
- The **100-test suite** covers real OCR, IPC, price caching, UI context, automatic area tracking, tray behavior, capture state and shortcuts. Platform-specific checks are skipped on other systems. The Linux package is checked with real pacman transactions and in isolated official Debian 12 / Ubuntu 22.04 filesystems, including dependency installation, offscreen and isolated X11 self-tests, installed-file checks and removal. Windows installer checks under Wine cover per-user installation, second launch, upgrade and uninstall while the app is open, complete application-file removal and user-cache retention. Wine builds/tests disable shortcut export to the Linux desktop.
- Automatic area detection defaults on. The fixed bottom status bar is the primary anchor; visible caption/frame pixels establish windowed bounds. Tests prove that moving/hiding the minimap or displaying/removing an FPS-like overlay does not alter the bounds, and that a first windowed detection works with the minimap hidden. Additional tests cover UI scales 0.8–1.5, movement, coverage, ambiguity and real OCR rejection of a readable shop outside the game area. Real reader-IPC tests prove old coordinates are cleared before a moved image is read, and that stationary shop frames skip OCR until a geometry check is due. Fingerprint patches retain their QImage storage until hashing finishes, avoiding allocator-dependent timeouts. The tests use public HUD fragments on generated desktops, never game input. A prior local OS capture also locates correctly with the FPS counter present; no physical minimap drag was automated.
- Minimize-to-tray defaults on, sends one OS notification per minimize transition and provides Show panel, Start/Pause/Resume, labels, Settings and Quit controls. Tests cover restoration, retained reading, preference persistence, unavailable-tray taskbar fallback and shutdown during a pending minimize. A Wayland timing regression checks that a normal-state server acknowledgment cannot erase a pending minimize request; explicit restoration cancels that request. The native KDE check verified our tray registration/menu, panel hiding, notification delivery and a visible notification toast without starting screen sharing. Our own user-only IPC supports minimization; hidden-app upgrade/removal uses the same explicit shutdown path. OS notification visibility depends on desktop preferences.
- The approved classic skill-style icon preserves the original v3 interior pixels with a corrected silver border, checked against a classic skill-list reference and black backgrounds before building. Seven native PNG sizes and all seven Windows ICO frames were compared exactly; the app supplies these sizes to avoid smooth resampling. The same icon appears in the panel, tray, native menu/installers and simplified GitHub README. Technical instructions are in `docs/TECHNICAL.md`; artwork research and prompt are in `docs/ARTWORK.md`.
- First-run UI checks cover friendly display names/diagram selection, explicit Start reading after selection, cancellation with late-result rejection, sharing failure with manual reconnect, hidden-label recovery without another capture request, bounded catalog retry and a marked example preview with no capture or item-price requests. Price-card checks distinguish recognised/no-data items, retain expanded details, remove comparisons immediately at the next UI tick when a price expires even within one age bucket, and reject mismatched world/item/condition/unit references throughout the panel and overlay. The optional hotkey/minimize prompt waits for an actual fresh priced annotation rather than an example or saved screenshot.
- Normal installed/portable launches wait for **Start reading**, even when a display is remembered. The explicit `--capture` option still supports automatic startup with a saved display. Advanced toggles, interval, shortcut and capture diagnostics are under Settings; always-on-top is optional and off by default. Main-panel/setup/price/settings renders use fake data and our own widget capture. These prove layout, not live game reading or native Windows acceptance.
- The unified Start/Pause/Resume button stays disabled without a valid display and while starting capture; sharing setup offers Cancel. A real local-stream test proves Pause/Resume retains one sharing session and skips paused-frame delivery, with capture rate reduced where supported. UI tests verify a pending reading cannot update paused prices or trigger refreshes. Sharing errors do not trigger an automatic picker loop.
- Hotkeys use Windows `RegisterHotKey`, the Wayland GlobalShortcuts portal, or a single X11 passive grab. An isolated Xvfb test registers a combination, sends keys only to that isolated server, observes activation, verifies conflicts and verifies release. Windows-binary checks register/reassign/unregister a chord and decode only our own simulated `WM_HOTKEY` message. Wayland checks cover real app-identity registration, session creation and listing on KDE, plus D-Bus wire shapes and early responses in controlled tests. **Live Wayland shortcut consent/physical activation and native Windows keyboard/capture behavior remain acceptance checks for their respective desktops.** No test sends input to a game.
- The new maple-leaf/magnifier icon is included in the app, Windows installer/shortcuts and Linux menu. Main-panel and hotkey-dialog renders use fake test data and our own widget capture; these are UI fixture evidence, not a new live game-capture test.
- Windows offline self-test passes real OCR, module loading, and independent overlay-helper stdin/stdout and OS-pointer reporting. This is Windows-binary compatibility evidence, **not a live Windows game/capture acceptance test**. The user will try that later.
- Inventory/equipment tooltip pricing is **on by default**, persists as a setting, and can be disabled. Shop-row labels take priority when the pointer is over the store list; tests verify no duplicate inventory label there while allowing inventory tooltips outside the list.
- NX/cash catalog data is loaded separately. Live source lookups succeeded for coupons, pet skills and cosmetics. White Jeans and Sailor Outfit resolve through the provider's unique current catalog entries. Blue Hawkeye's live source response also contains a price; narrow y/v glyph correction handles the Classic font's known OCR confusion without unconstrained fuzzy matching.
- The MesoWatch import button is removed. Known `fm_not_tradeable` HTTP 400 responses become a cached source-coverage result rather than a raw error or a claim about what the game permits. Errors from earlier stores no longer remain on the status line.
- API-count tests run 500 repeated item reads with **one price-summary request**, and only one new request at the cache boundary. Successful empty, unsupported and old-data responses retain the same 15-minute HTTP cache lifetime, independently of whether the market data is fresh enough for a deal rating. Item-ID discovery is separately cached. Network failures use a retry cooldown.
- Streaming capture reuses one OS sharing session across UI handoffs. It crops a shared workspace to the selected monitor; no repeated Spectacle startup/PNG compression in the fast path. Latest-frame delivery uses backpressure, unchanged shop pixels skip OCR, and known shops use a small capture region.
- A live sample after the streaming changes measured about **200 ms median / 276 ms p95 capture-to-reading delay**. A later sample measured about **181 / 200 ms**. These are reading-pipeline timings, not promises for an uncached remote-price request.
- A 15-second sample across the four app processes measured about **7.1% of this 12-logical-CPU machine and 449 MiB proportional RAM**, with three-display workspace capture. Earlier unthrottled capture used more CPU. These are local samples under changing game content, not a controlled cross-machine benchmark. Windows captures the selected monitor and caps capture at 10 FPS where supported.

## Initial live calibration

**Live on Manjaro KDE Wayland:** the game was already running with the user's own Classic World shop open. All observations came from normal OS screenshots. No game input was sent.

- The reader identified Green Bamboo Hat, Weighted Earrings and the truncated Overall Armor LUK Scroll listing. The gold scroll icon uniquely resolved the latter to **Overall Armor LUK Scroll: Greater**.
- It read their prices as 2,000 / 10,000 / 20,000 mesos, quantity one each. The grey sold-out Brown Bamboo Hat was omitted.
- Real NiaMeowDB Classic World requests resolved game IDs to database IDs `790`, `901`, `141`, verified by both item name and `iconKey`. The cached 24h reference medians were 2,500 / 5,555 / 17,999 mesos when checked. These are dated observations, not permanent price recommendations.
- The final rendered OS screenshot shows small item names above the references, with −20% / +80% / +11% and visible cache ages. Equipment uses the user's explicit **unscrolled assumption**, with no stats question mark.
- Labels are drawn by a separate, independent XWayland window. A direct query of **our own test annotation window's** X11 input shape returned **zero input rectangles**. This verifies click transparency without clicking or sending input to the game. Its screen origin was `(1920, 0)` after correcting KDE's initial vertical placement shift.
- The vendor checkout remains unchanged. The runtime bridge links only its headless core. No game-specific OS adapters from upstream run.

**Automated checks:** 18 tests passed, including real OCR fixtures for ore/gem names and prices, scroll tiers and sold-row omission; cache expiry boundaries; failed refreshes; wrong-world and wrong-ID rejection; bundle/set normalization; and unscrolled-equipment comparisons. `cargo check --locked --manifest-path reader/Cargo.toml -j 2` passed.
